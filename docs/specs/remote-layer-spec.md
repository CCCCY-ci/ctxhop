## 1. 范围

**在范围内**：存储布局的落地、分片格式与版本判定所需的元信息、`dir` driver、`s3` driver、最终一致性下的读取语义。

**不在范围内**：加密（单独的 crypto spec，本层只搬运不透明字节）、同步编排、CLI。Google Drive 等 OAuth 类后端按 PRD §8.4 排在 P2，本次不做。

---

## 2. 布局要解决的问题

PRD §8.3 定下的原则是**任意两台设备永不写同一个对象**，使存储层退化为哑管道（P3）。但仅有"各写各的"还不够——读取方必须能把不同设备写的分片**排成一条会话**，并判断谁是谁的前缀。

会话是记录序列。设备 A 有记录 `[0,100)`，推送后设备 B 拉取、继续到 150，推送 `[100,150)`。读取方看到两个分片，必须知道它们首尾相接。

### 2.1 仅靠序号不够

若分片只声明"我从第 100 条开始"，两台设备各自从 100 继续时会产生两个都声称 `base=100` 的分片——这是分叉信号没错，但**无法确认它们此前真的共享同一段历史**。前 100 条也可能早已不同。

### 2.2 前缀摘要

因此每个分片携带 **`prefixDigest`**：其 `base` 之前所有记录的累积摘要。

```
分片 = { base, count, prefixDigest, records[] }
```

判定规则：

| 情况 | 判定 |
|---|---|
| 远端分片 `base == 本地记录数` 且 `prefixDigest == 本地摘要` | 远端在延续本地 → **快进** |
| 本地记录数 > 远端 `base`，且本地在该点的摘要与之相同 | 本地领先 → 正常推送 |
| 两个分片 `base` 相同、`prefixDigest` 相同、内容不同 | **分叉**，且分叉点确切已知 |
| `prefixDigest` 不同 | 更早就已分叉，需回溯共同前缀 |

摘要必须计算在**规范化记录**上。这正是 adapter spec §3 要求确定性重编码的原因——若同一条逻辑记录在两台设备上字节不同，摘要必然不同，一切判定失效。PoC-1b 已在真实数据上验证了该性质。

## 3. 存储布局

```
<root>/
  v1/
    projects/<project-id>/
      project                       项目元信息（每设备一份，见下）
      sessions/<session-id>/
        <device-id>/
          meta                      该设备对该会话的元数据
          000001                    分片，序号单调递增、定宽零填充
          000002
    devices/<device-id>             设备自述
```

约束：

* **每台设备只写 `<device-id>/` 下的对象**，只读其他设备的。写路径不重叠，因此不存在并发写同一对象的可能（BR-03）。
* **分片一旦写入即不可变**（BR-04）。重传是幂等的：同样的键写同样的内容。
* 分片文件名的序号**只用于该设备内部的顺序**，全局排序一律由分片头的 `base` 决定。定宽零填充使字典序与数值序一致，便于列举。
* `project-id` 与 `session-id` 必须是**密钥派生的不可逆值**，不得直接使用 Git 远端地址或原生会话 ID——否则仅凭对象列表即可推断用户在做什么项目。具体派生方式属于 crypto spec。

### 3.1 分片格式

分片是**不透明字节**，对本层而言没有结构。头部字段（`base`/`count`/`prefixDigest`）属于**加密后的载荷内部**，由上层解析——本层若能读懂头部，就意味着明文可被存储方看见，违反 P6。

因此：**Remote 层不解析分片，也不做版本判定。** 它只负责按键读写字节、列举键、报告不存在。判定发生在 syncer，那里已经持有密钥。

> 这条边界很容易被侵蚀。任何想让 `remote` "顺便看一眼 base 好排序"的改动都必须被拒绝——那等于把明文暴露给存储层。

## 4. `Remote` 接口是否够用

现有接口为 `Name/List/Get/Put/Delete/Stat`，外加可选的 `Prober`。

结论：**够用，不扩充**。

* 不需要条件写（compare-and-swap）：键由设备独占，分片不可变，不存在竞争。
* 不需要锁或事务：见上。
* 不需要范围读：分片体积由上层控制，整取即可。
* 不需要批量删除：删除是低频操作。

保持最小是有意的——每多一个方法，就多一类后端可能不支持，而 P3 要求后端可以是 U 盘。

---

## 5. 最终一致性

S3 类后端的列举可能滞后于写入。这带来两条硬规则。

### 5.1 「未列出」永远不等于「对方没写」

这是 PRD §2.4 已经点名的陷阱的同类：把暂时看不到当成不存在，会让同步层误判其他设备没有数据，进而错误地判定分叉或覆盖。

因此：

* 设备**自己**的推送进度记录在本地，不从 List 反推。否则一次列举滞后就会让它重写已经写过的序号，产生重复。
* 读取方发现分片不连续时，**不得**把已有的部分当成完整会话。

### 5.2 连续性必须显式校验

若存在 `[0,50)` 与 `[100,150)` 而缺失 `[50,100)`，读取方**绝不能**返回一个中间缺失的会话——那会写出一份看起来正常、实则丢了 50 条记录的会话，用户无从察觉。

正确行为：检测到空洞即报告，区分两种情况：

| 情况 | 行为 |
|---|---|
| 刚推送过，可能只是列举滞后 | 提示稍后重试，不写入 |
| 持续缺失 | 报告该会话不完整并指出缺口范围，不写入 |

## 6. `dir` driver

把根目录当对象存储用。用途有二：集成测试的基础设施；以及让用户把仓库放进已有网盘目录直接起步。

要求：

* **键必须校验**后才拼进路径。含 `..` 或绝对路径成分的键必须拒绝——与 adapter 的 session id 校验同源，这是又一处"外部输入拼进文件路径"的地方。
* **写入必须原子**（临时文件 + rename），否则被第三方同步工具看到的可能是半个分片。
* 列举不跟随符号链接走出根目录。
* 目录不存在时按需创建；`Get` 不存在的键返回 `remote.ErrNotFound`。

## 7. `s3` driver

### 7.1 不引入 SDK

自行实现 SigV4 签名，零第三方依赖。理由：

1. 只用 5 个操作（ListObjectsV2 / GetObject / PutObject / DeleteObject / HeadObject），SDK 的绝大部分用不上。
2. 项目至今零依赖、二进制 1.6MB；`aws-sdk-go-v2` 会把体积推到 10MB 量级，而单文件小体积是 CLI 分发体验的一部分（code_style §6）。
3. **签名错误的失败方向是有利的**：请求被拒（403），响亮且立即可见，不是静默损坏。这与 adapter 层"猜错就静默写坏数据"的风险性质完全不同。
4. 自行实现可完全控制 **path-style 寻址**——MinIO 与部分厂商需要它。

> **退路**：若 SigV4 在某些厂商上出现无法收敛的兼容性问题，退到 `minio-go`（一个适中的依赖），而**不是** `aws-sdk-go-v2`。该决定需记录在本 spec 中再执行。

### 7.2 配置项

endpoint、region、bucket、access key、secret key、路径前缀、寻址方式（path-style / virtual-host，默认 path-style）。

凭据不得明文写入配置文件，也不得出现在进程参数中（code_style §5.3）；支持从环境变量提供。

### 7.3 必须正确处理

* **`NoSuchKey` / 404 映射为 `remote.ErrNotFound`**；**其他任何错误一律不得映射为 ErrNotFound**。把传输故障当成"对象不存在"，会让同步层断定其他设备没推过东西（PRD 明确点名的错误）。
* List 的分页（continuation token），不得只取第一页。
* 所有请求必须有超时，后端不可达时快速失败（§11.2）。
* 重试限于幂等操作与可重试状态码，需退避；不得无限重试。
* 错误信息必须指出下一步（例：`cannot reach bucket "x": check endpoint and credentials with 'agentsync doctor'`），且不得包含凭据。

---

## 8. 绝不能做的事

1. **绝不解析分片内容**。本层看到的一切都是不透明字节。
2. **绝不把传输故障映射为「不存在」**。
3. **绝不写入其他设备的键前缀**。
4. **绝不修改已写入的分片**。
5. **绝不把「未列出」当作「不存在」向上层报告为确定结论**。
6. **绝不在校验键之前把它拼进文件路径**。
7. 绝不在日志或错误中输出凭据、完整对象键或路径前缀。

## 9. 测试计划

覆盖率目标 90%+（testing.md 对 `internal/remote` 的要求）。

* **契约测试**：一套用例同时跑在 `dir` 与 `s3` 上，保证两者行为一致。`s3` 侧用 `httptest` 伪造 S3 响应，不依赖真实账号。
* **SigV4**：对照 AWS 公布的测试向量断言规范请求与签名字符串。
* **ErrNotFound 边界**：404 → ErrNotFound；500 / 超时 / DNS 失败 / 连接重置 → **不得**是 ErrNotFound。
* **分页**：多页列举必须取全。
* **键校验**：`..`、绝对路径、反斜杠、空键一律拒绝，且拒绝时不得创建任何文件。
* **原子性**：`dir` 写入中断后目录中不得出现半个分片，也不得残留临时文件。
* **path-style 与 virtual-host** 两种寻址各自的 URL 构造。
* **最终一致性**：模拟 List 滞后，断言上层能区分"缺口"与"确实没有"。

## 11. 未决

1. 分片的目标大小与切分策略（太小则对象数爆炸，太大则单次重传代价高）。倾向按记录数与字节数双阈值切分，具体数值待实测。
2. 会话历史的裁剪策略（PRD §9.8 的清理命令）如何与不可变分片共存。
3. 网盘目录作为 `dir` 后端时，第三方同步工具的部分同步状态是否会让读取方看到半个分片——PoC-3 应覆盖此项。
