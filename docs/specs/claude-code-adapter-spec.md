## 1. 范围

实现 `internal/adapter` 的 Claude Code 版本，以及本文定义的**规范化表示**。

**在范围内**：Agent 检测与兼容性分级、会话发现、安全读取、规范化与本地化、原子写回、触碰文件提取、hook 注册。

**不在范围内**：加密、远端存储、同步编排、冲突处理的产品逻辑、Codex。这些消费本 Adapter 的输出，但不由它实现。

## 2. 已知的磁盘结构（PoC-1 实测）

```
~/.claude/projects/<slug>/<session-id>.jsonl
```

`slug` 由项目绝对路径编码而成。规则**已从 Agent 自身实现中读出并实测确认**：

```js
// 把每一个非 ASCII 字母数字的字符替换为 '-'
slug = path.replace(/[^a-zA-Z0-9]/g, "-")
// 超过 200 字符则截断，并追加原路径哈希的 base36
if (slug.length > 200) slug = slug.slice(0, 200) + "-" + Math.abs(hash(path)).toString(36)
// hash: h = h*31 + charCodeAt(i)，int32 环绕
```

因此**不只是分隔符**：`_`、`.`、空格、以及每一个非 ASCII 字符都各变成一个 `-`。实测样本：

```
D:\CodeWorkSpace\poc_slug test.v2_名字
→ D--CodeWorkSpace-poc-slug-test-v2---
```

该规则由 JavaScript 实现，因此**跨平台一致**，POSIX 路径的 `/` 同样落入"非字母数字"分支，无需单独验证。

由于是 JS 实现，替换与哈希都按 **UTF-16 码元**进行：基本多文种平面之外的字符占两个码元，因此产生两个 `-`。Go 侧必须以 `utf16.Encode` 迭代，不能按 rune。

> 编码必须与 Agent **完全一致**。近似的实现会指向一个 Agent 从不读取的目录：发现阶段找不到会话因而静默不备份，恢复阶段报告成功但 `--resume` 看不到。两种失败都是无声的。

**该编码不出现在文件内容中**，因此恢复时只需在文件系统层面放到正确的目录，无需在内容里查找替换。

编码是**高度有损**的：`my_app`、`my-app`、`my.app` 产生同一个 slug。因此**不实现反解码器**，会话归属哪个项目一律以会话内的 `cwd` 为准。

会话是 JSONL，每行一条记录。实测出现的记录类型：`user`、`assistant`、`system`、`attachment`、`ai-title`、`last-prompt`、`mode`、`permission-mode`、`file-history-snapshot`、`file-history-delta`。

Adapter **不需要理解**这些类型的语义，只需要按字段白名单处理路径，并保持其余内容不变。

## 3. 核心架构决策：远端存储规范化形式

### 3.1 问题

PRD §9.6 的版本判定依赖"本地是远端的严格前缀"。但会话内容与设备绑定：设备 A 的记录里写着 `D:\...\Example`，设备 B 上同一条记录写着 `/Users/u/Example`。

若远端直接存设备本地字节，则 A 与 B 推送的同一条逻辑记录字节不同，**前缀比对永远判定为分叉**，快进机制失效，产品的版本模型崩溃。

### 3.2 决策

**远端存储规范化记录（canonical record）。**

规范化 = 对每条记录做两件事：

1. **路径令牌化**：把白名单字段中属于项目根或 Agent 数据目录的路径，替换为占位符 + 正斜杠相对路径。
2. **确定性重编码**：以稳定规则重新序列化 JSON，使任意设备对同一条逻辑记录产生完全相同的字节。

```
本地字节 ──规范化──> 规范化记录 ──> 加密 ──> 远端
远端 ──> 解密 ──> 规范化记录 ──本地化──> 本地字节
```

版本判定、前缀比对、分叉检测**一律在规范化记录上进行**，不在本地字节上进行。

### 3.3 令牌形式

| 令牌 | 含义 |
|---|---|
| `${AS_PROJECT}` | 项目根目录 |
| `${AS_AGENT_HOME}` | Agent 数据目录（`~/.claude`） |

令牌之后的剩余路径统一使用正斜杠：

```
"cwd": "D:\\CodeWorkSpace\\VSCodeProjects\\Example"   →  "${AS_PROJECT}"
"file_path": "D:\\...\\Example\\src\\a.go"            →  "${AS_PROJECT}/src/a.go"
```

不属于这两个前缀的绝对路径**保持原样**，不做猜测性改写（延续 PoC-1 的决策）。此类路径在目标设备上可能无效，属于已知取舍。

### 3.4 确定性重编码规则

任意设备对同一逻辑记录必须产生相同字节，因此规则必须完全确定：

1. 对象键按字节序升序排列（Go `encoding/json` 对 `map[string]any` 的既有行为）。
2. **关闭 HTML 转义**（`SetEscapeHTML(false)`），否则 `<`、`>`、`&` 会被转成 `\u003c` 之类，与原文不一致。
3. **数字必须原样保留**：解码时使用 `json.Number`（`Decoder.UseNumber()`），禁止走 `float64`。否则大整数会变成 `1e+06` 之类的表示，既改变字节也可能损失精度。
4. 不缩进、不追加空白，每条记录一行。

### 3.5 为什么不做字节级替换

字节级替换能完整保留原始字节，但存在两个问题：一是必须处理 JSON 字符串转义（Windows 路径在 JSON 里是 `D:\\...`），二是**无法区分字段**——项目路径同样出现在对话正文和终端输出里，而那些位置按 PoC-1 的结论必须保持不动。要做到字段感知就必须解析，解析之后重编码是更简单且可验证的路径。

PoC-1 已经实测确认：重新序列化后的会话可以被原生 `--resume` 正常继续。

### 3.6 副作用与接受理由

本地文件在被 AgentSync 写入后，键顺序与 Claude Code 原生写出的不同，且此后 Claude Code 会在其上继续追加原生格式的记录，文件成为混合表示。

这**不构成问题**，因为规范化在每次读取时重新计算，比对永远发生在规范化形式上，本地文件长什么样不影响判定。

### 3.7 同步单元是记录，不是字节

由于本地字节与规范化字节不等长，字节偏移无法作为同步位置。

**同步单元为完整记录。** 分片包含整数条规范化记录；版本关系为"记录序列的前缀关系"。这同时天然避免了读到半行的问题。

> 该决策影响 PRD §8.3 与 §9.4，需同步更新。

## 4. 接口实现设计

### 4.1 `Detect`

1. 定位可执行文件与 `~/.claude`（支持 `CLAUDE_CONFIG_DIR` 覆盖，若存在）。
2. 读取版本号。
3. 按 §4.8 判定兼容性级别。
4. 未安装返回 `ErrNotInstalled`，不视为错误。

### 4.2 `DiscoverSessions`

遍历 `~/.claude/projects/*/*.jsonl`。

* **不从 slug 反解项目路径**（编码有损，见 §2）。以会话内的 `cwd` 与 `projectPath` 比对，不一致则跳过——`my_app` 与 `my.app` 共用同一个 slug 目录，不校验就会把别的项目的会话推上去，或把恢复的会话装进错误的项目。
* 发现阶段使用**宽容读取**：中间损坏的记录跳过并计数，会话仍然出现在列表里。被杀死的写入会留下半行、Agent 随后在其后继续追加，这恰好产生中间损坏；若因此丢弃整个会话，用户会看到它凭空消失且永不备份。要推送的路径仍用严格读取，因为分片一旦写入不可变。
* 一条有效记录都读不出的文件不计为会话。
* 会话目录路径上存在非目录文件时必须报错。Windows 上 `ReadDir` 对文件返回的错误与"目录不存在"无法区分，需用 `Stat` 二次确认，否则会把"挡住了"报告成"没有会话"。
* `NativeID` = 文件名去掉 `.jsonl`。
* 时间戳优先取记录内字段，缺失时回退到文件 mtime。
* 标题按 PRD §9.2.1 的四级优先级生成，其中"Agent 自身摘要"对应 `ai-title` 记录。
* 单条记录解析失败**不导致整个发现失败**，跳过并计数。

### 4.3 `ReadSession`（安全读取）

Agent 可能正在追加写入，最后一行可能只写了一半。

规则：**逐行解析，只返回到最后一条完整且合法的记录为止**；末尾不完整的行丢弃，不报错。

宁可少返回一条记录，也绝不返回半条——半条记录一旦被规范化并推送，会污染远端的记录序列，而分片是不可变的。

不加锁、只读打开，不修改文件的任何元数据。

### 4.4 `Rewrite`（本地化）

输入规范化记录，输出目标设备的本地字节。

* `${AS_PROJECT}` → 目标项目根；`${AS_AGENT_HOME}` → 目标 Agent 数据目录。
* 正斜杠转为目标平台分隔符。
* **令牌必须整体位于字符串值开头**才替换；出现在中间视为异常，中止并报错，不做部分替换。
* 任一记录失败即整体失败，不写入 Agent 目录（BR-10）。

### 4.5 路径字段白名单

值为路径的叶子字段：

| 字段 | 前缀类别 |
|---|---|
| `cwd` | 项目 |
| `file_path` | 项目 |
| `filePath` | 项目 |
| `planFilePath` | 项目 |
| `trackingPath` | 项目 |
| `realParentDir` | Agent 数据目录 |

键为路径的容器：`trackedFileBackups`（其**键名本身**是绝对路径，只改写值会静默漏掉）。

**遇到白名单之外、但值看起来是绝对路径的字段，必须记录并在诊断中可见**，避免 Claude Code 新增字段后我们无声地漏掉它。这是 PoC-1 中报告缺陷的直接教训：当时的"未改写"统计只检查字符串开头，漏报了嵌在文本中的路径。

### 4.6 `WriteSession`（原子写）

0. **校验 session id 是否是安全的文件名**。native id 来自其他设备的元数据，含 `..` 或分隔符的 id 直接拼进路径会走出 `~/.claude/projects/<slug>/`，而 `MkdirAll` 会一路把目录建好。这是唯一写入 Agent 数据目录的代码路径，无法确认安全就必须拒绝（BR-12）。
1. 确保目标 slug 目录存在。
2. 写入**同目录**下的临时文件（跨卷 `rename` 不是原子的）。
3. `Sync()`。
4. `Rename` 覆盖。
5. 失败时删除临时文件，不留半写入状态（BR-11）。

### 4.7 `TouchedFiles`

扫描 `tool_use` 块，取 `name` 与 `input.file_path`。

* 写工具：`Edit`、`Write`、`MultiEdit`、`NotebookEdit`。其余按读处理——**多报一次读只多算一次哈希，漏报一次写会让过期文件溜过去**，保守方向是把未知工具当读。
* 只返回项目内路径，项目外的丢弃。
* 返回正斜杠的项目相对路径。

**已知且不可消除的缺口**：PoC-2 实测显示约 40% 的工具调用是 shell 命令，不记录所改文件。因此该集合**不足以**作为一致性检查的唯一依据，必须由 Git 脏文件集兜底（PoC-2 §3）。Adapter 只负责提供这个集合，不负责闭合缺口。

### 4.8 兼容性分级

| 级别 | 条件 | 行为 |
|---|---|---|
| `CompatFull` | 版本在已验证列表内 | 正常读写 |
| `CompatLimited` | 版本未知，但记录可解析且未出现白名单外的路径字段 | 继续推送备份，恢复需显式确认 |
| `CompatStopped` | 记录无法解析，或出现未知的路径字段 | 停止读写，保留已有数据 |

版本列表与字段白名单以数据形式维护，便于不发新二进制即可更新。

### 4.9 `HookInstaller`

在 Claude Code 的设置中注册会话结束时调用 `agentsync push` 的 hook。必须幂等，必须只增删自己的条目，不得影响用户已有 hook。

## 5. 失败与边界设计

| 场景 | 行为 |
|---|---|
| 会话最后一行不完整 | 丢弃该行，返回前面的完整记录，不报错 |
| 记录中出现白名单外的绝对路径字段 | 降级为 `CompatStopped`，不写入 |
| 令牌出现在字符串中间 | 中止本次本地化并报错 |
| 目标 slug 目录不存在 | 创建；创建失败则中止，不写入 |
| 写入中途失败 | 删除临时文件，保持原状 |
| 项目根为空或不存在 | 拒绝执行本地化 |
| 同名会话已存在于目标 | 交由上层决定，Adapter 不自行覆盖 |
| Agent 未安装 | 返回 `ErrNotInstalled`，不报错 |

### 绝不能做的事

1. 绝不锁定、移动或修改 Agent 正在使用的文件。
2. 绝不返回或推送不完整的记录。
3. 绝不对项目外的路径做猜测性改写。
4. 绝不在未完成令牌替换的情况下写入 Agent 目录。
5. 绝不非原子地写入 Agent 目录。
6. 绝不在遇到未知结构时"尽力而为"——一律降级并停止写入。

## 6. 测试计划

按 testing.md，本包覆盖率目标 **95%+**，且测试全部入库、夹具全部合成。

### 6.1 规范化 ↔ 本地化的对照测试

采用表驱动测试，期望值内联在用例中，而非放在 `testdata/golden/` 的独立文件里。规范化记录是单行 JSON，内联时用例与期望并排可读、diff 直观；拆成文件反而需要在两处之间来回跳。若将来出现整段会话级别的夹具，再引入 `testdata/`。

需覆盖：

* Windows → POSIX、POSIX → Windows
* 含空格、非 ASCII 的路径
* **Windows 路径的分隔符混用**（`D:/a/b` 与 `D:\a\b` 必须视为同一目录）
* 大小写不一致的路径前缀（Windows 折叠大小写，POSIX 不折叠）
* 项目外绝对路径（必须原样保留）
* `trackedFileBackups` 的键改写
* 嵌套对象内的字段
* 数字字段（大整数、小数、指数形式）必须原样保留

### 6.2 往返性质测试

对任意合成会话：`localize(canonicalize(x))` 在同一设备上必须等价于 `x`（键顺序可不同，但解析后的结构必须一致）。

### 6.3 确定性测试

同一逻辑记录，在不同键顺序、不同空白、不同平台路径写法下，规范化结果必须**字节相同**。这是前缀比对成立的前提，必须显式断言。

### 6.4 安全读取

* 末行截断 → 返回 N-1 条
* 末行为空白 → 忽略
* 中间行损坏 → 按 §4.2 计数并跳过（发现）/ 按 §4.8 停止（读取）

### 6.5 原子写入

模拟写入中途失败，断言目标目录不存在半写入文件，且原文件未被破坏。

### 6.6 模糊测试

`FuzzCanonicalize`：任意字节输入不得 panic、不得写盘。

## 9. 未决与待验证

1. Claude Code 是否会因键顺序变化产生任何行为差异——PoC-1 单样本验证通过，需要更多样本。
2. `memory/` 子目录的用途未知（PoC-1 §3.7），需持续观察是否承载必须同步的内容。
3. 跨用户名的 `${AS_AGENT_HOME}` 改写未实测（PoC-1 中源与目标相同）。
4. 长路径的哈希分支已按 Agent 的算术实现并用交叉验证的值断言，但**尚未在真实的超长路径项目上端到端验证**。

### 已解决

* **slug 编码规则**：已从 Agent 实现中读出并实测确认，见 §2。跨平台一致，无需单独验证 POSIX。
* **令牌与用户内容冲突**：不再视为错误。令牌只写入白名单位置，因此其他位置出现同样的字符是用户内容，本地化时原样保留。否则任何讨论 AgentSync 自身的会话都将无法恢复——包括开发它时产生的那些。
