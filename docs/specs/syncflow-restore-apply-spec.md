# Spec: syncflow restore application

| | |
|---|---|
| Status | Draft |
| Date | 2026-08-14 |

## 1. Scope

This increment applies an already localised `RestorePlan` only after checking
the target workspace against the source `project.Fingerprint`. It is the first
layer allowed to call an Agent adapter's session writer.

The source fingerprint is supplied as an input because its remote metadata
transport is a separate format decision. A missing fingerprint is an error;
the application never treats missing evidence as a clean workspace.

## 2. Apply order

`ApplyRestore` performs these steps in order:

1. validate context, writer, target project, session ID, plan, fingerprint,
   and compatibility consent;
2. call `project.Compare` for the target project;
3. refuse a `Divergent` report unless the caller explicitly allows it;
4. check cancellation again;
5. call `WriteSession` or, only when explicitly requested, `ReplaceSession`.

No Agent write occurs for any failed precondition or divergent workspace. The
`Consistent` and `Explainable` verdicts are accepted; the report is returned
with the result so callers can surface an explainable difference before the
user resumes the session.

The adapter owns JSONL validation, target directory creation, session ID path
safety, and atomic publication. This layer does not construct a path under the
Agent data directory and does not provide a non-atomic fallback.

## 3. Explicit decisions

`RestoreApplyOptions` contains three opt-in decisions:

* `AllowLimited` permits applying a plan produced for an unverified Agent
  version;
* `AllowDivergent` permits writing despite a workspace `Divergent` verdict;
* `ReplaceExisting` selects the adapter replacement operation instead of the
  create-only operation.

All three default to false. `ReplaceExisting` does not by itself authorise a
divergent workspace; both decisions are independent.

## 4. Failure and durability

The returned `RestoreApplyResult` preserves a workspace report when comparison
completed but the write was refused. Errors retain sentinels for missing
fingerprints, divergent workspaces, invalid plans, workspace comparison
failures, and adapter writes. Adapter errors such as `ErrSessionExists` remain
discoverable through `errors.Is`.

The writer API is synchronous and atomic. Context cancellation is checked
before the write; once the adapter call begins, its atomic operation is allowed
to finish and its result is authoritative.

No error generated by this layer includes record contents, local roots, or
credentials. Workspace file names are available only in the structured
`project.Report`, where they are needed for an intentional user-facing
consistency decision.

## 5. Test plan

Local tests cover missing evidence, limited compatibility, invalid plans and
session IDs, consistent and explainable reports, divergent refusal and explicit
override, create versus replace writes, adapter error propagation, context
cancellation, and the guarantee that no writer call happens before the
workspace decision.
