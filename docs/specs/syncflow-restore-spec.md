# Spec: syncflow restore planning

| | |
|---|---|
| Status | Draft |
| Date | 2026-08-14 |
| Depends on | `syncer` remote branch reads, `adapter` path localisation |

## 1. Scope

This increment composes the existing remote read and version-resolution
primitives into a non-destructive restore plan. It may list and read encrypted
remote shards, resolve consistent, fast-forward, or forked versions, and
localise the selected canonical records for the target machine.

It does not write the Agent directory, modify a workspace, update a cursor, or
publish remote objects. A later apply step must perform workspace fingerprint
checks and use the adapter's atomic installation operation.

The public entry points are:

* `PlanRestore`, which plans from an already resolved `syncer.Resolution`;
* `FetchRestorePlan`, which reads one remote session and then calls the same
  planning path.

Keeping the pure and I/O entry points separate makes fork selection and path
rewriting testable without touching a remote backend or a local Agent.

## 2. Preconditions

The target `PathSpace` must contain both a project root and an Agent data root.
The restore planner refuses a missing root before remote I/O. It never guesses
either root from a session token or from the remote object key.

Compatibility is a write-safety gate:

| Compatibility | Restore behavior |
|---|---|
| `CompatFull` | Allowed |
| `CompatLimited` | Allowed only when the caller explicitly sets `AllowLimited` |
| `CompatStopped` | Refused |
| `CompatUnknown` | Refused until detection has classified the installation |

The compatibility reason is diagnostic metadata supplied by the adapter and
must remain safe to display. A refusal happens before remote reads.

## 3. Version selection

`syncer.ResolveBranches` already removes strict prefix branches and preserves
every maximal incomparable branch. A resolution with one maximal version is
selected automatically. A fork requires a non-nil `VersionIndex`; omitting it
returns `ErrForkSelectionRequired`. An index outside the resolution is
rejected, and no branch is silently discarded.

The selected version is revalidated before localisation. Its records must be
canonical and its stored head digest must match the record sequence. The
planner copies both canonical and localised record buffers so later caller
mutation cannot change an accepted plan.

## 4. Localisation

Every selected canonical record is passed through `adapter.Localize`. The
adapter remains responsible for token semantics, path-keyed containers,
separator differences, and rejecting malformed token placement. A localisation
failure aborts the whole plan; a partially localised sequence is never
returned.

The planner checks the context before and between blocking remote reads. A
cancelled context or a remote read error is returned with its cause wrapped.
Remote listing gaps, missing objects, duplicate shards, malformed ciphertext,
and invalid envelopes retain the `syncer` error sentinels so the caller can
choose retry or user-visible handling without parsing error strings.

## 5. Safety boundary

The plan contains records in memory only. It never calls `WriteSession` or
`ReplaceSession`, and it never creates or removes files. Applying a plan is a
separate operation that must establish the workspace relationship, require
explicit confirmation for a limited installation, and perform one atomic
adapter write.

No error or diagnostic generated by this layer may include record contents,
local roots, project names, session identifiers, credentials, or backend
addresses.

## 6. Test plan

Local tests cover successful remote fetch and localisation, deterministic fork
selection, refusal of unconfirmed or stopped compatibility, missing path
spaces, invalid version metadata, malformed token localisation, cancellation,
and buffer independence. The tests remain local under the repository's
`.gitignore` policy.
